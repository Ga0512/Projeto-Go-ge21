# Dados persistentes para Pods em qualquer região

Um Network Volume expõe a API S3 em
`https://s3api-<datacenter-do-volume>.runpod.io/`. O ID do volume é o nome do
bucket. Um GPU Pod em outra região acessa esse endpoint por rede, sem montar
o volume. O volume atual é `g643dn7nah` (`projeto-go-s3`, `US-GA-2`), e o
dataset `wv_jatai_v4` fica em `Data/dados/datasets/wv_jatai_v4/`.

O código continua vindo do GitHub e usa os mesmos scripts do PC. Só o fluxo
RunPod usa `runpod/executar_s3.py` para baixar entradas e devolver resultados.
O treino e a inferência locais continuam iguais.

## Preparar o GPU Pod

Forneça ao Pod as **credenciais S3** (`AWS_ACCESS_KEY_ID`,
`AWS_SECRET_ACCESS_KEY`) como variáveis de ambiente privadas. Elas são
diferentes da chave da API RunPod. Não grave credenciais no Git ou nos logs.
Defina também:

```bash
export RUNPOD_VOLUME_ID=<id-do-volume>
export RUNPOD_DATACENTER=<datacenter-do-volume>
export DATASET=<nome-do-dataset>
export RUN=<nome-do-run>
```

Clone o repositório e prepare `Data/.venv` conforme o ambiente do projeto.
Instale `boto3` nessa venv. A GPU e o GDAL são requisitos dos scripts de
treino/inferência, não da transferência S3.

## Treinar

No Pod, a partir de `Models/`, execute, ajustando nome e argumentos do run:

```bash
../Data/.venv/bin/python ../runpod/executar_s3.py \
  --entrada "Data/dados/datasets/$DATASET" \
  --saida "Models/unet_cnn/runs/$RUN/modelo_melhor.pth" \
  --saida "Models/unet_cnn/runs/$RUN/relatorio.json" \
  --saida "Models/unet_cnn/runs/$RUN/log.csv" \
  -- ../Data/.venv/bin/python -u unet_cnn/train.py \
       --nome "$RUN" --dataset "../Data/dados/datasets/$DATASET" \
       --arquitetura unetpp --base 32 --lote 20 \
       --epocas 20 --paciencia 5 --reamostrar --reamostrar-k 3
```

O wrapper baixa o dataset, roda o comando em `Models/` e envia as saídas
indicadas para as mesmas chaves no S3, inclusive quando o comando retorna erro.
Um Pod que continua ligado executa isso sem o PC. Para fechar o SSH sem encerrar
o processo, inicie com `nohup` e redirecione o log para arquivo no Pod.
Depois do upload, confira os objetos por S3 e pare o Pod para encerrar a cobrança.

## Inferir

Use o mesmo wrapper, agora com entradas para o checkpoint, a PAN, o TIFF NDVI
temporal e o dataset. Indique como saídas `classes.tif`, `classes.png`, `info.json`
e os logs necessários. O comando de `unet_cnn/inferencia_cena.py` segue o
docstring dele; as opções de bandas precisam corresponder ao `receita.json`.
Se a cena for grande, confira o espaço livre do Pod e do volume para o mapa.

## Conferir do PC, quando desejar

```bash
../Data/.venv/bin/python ../runpod/subir.py \
  --volume "$RUNPOD_VOLUME_ID" --datacenter "$RUNPOD_DATACENTER" --listar
```

O PC é necessário só para baixar uma cópia local depois; o Pod faz as
transferências do treino e da inferência diretamente com o S3.
